# WO-035 — P20 output capacity dependencies and standard resolutions

**Status: DONE (2026-11-10 — 185 offline tests, captured P20 XML and mock Chrome; live hardware acceptance pending)**

## Investigation FIRST

Owner's P20 lacks output DL/4K controls and per-output standard resolutions. Follow-up to WO-005/014/032.

- `lib/studio-outputs.js` only normalizes capacity, rejects it as a change, and always sends timingSelect=3. `public/outputs-ui.js` displays capacity as text and has only width/height/Hz per port; its bulk list is a small hardcoded list. Standard mode is therefore absent from individual rows.
- P20 installed output card 15728897 advertises `CapacityGroups` DL=1 and 4K=2 in its XML. Mode 4 (Switcher) DL exposes independent physical HDMI 1/3/5/7, paired copies 2/4/6/8. Switcher 4K exposes independent 1/5, copies 2/3/4 from 1 and 6/7/8 from 5. Mode 8 (PGM-only/splicer) keeps 1/3/5/7 independent at both capacities. Use XML, current working mode and actual interface IDs, not per-port capacity toggles. Optical, AUX/MVR and input connectors remain separate.
- PixelFlow `input-subcard-attr/InputSubcardAttr.tsx:604,879,1003` changes all HDMI outputs on the card, checks usage and warns normal screens may reset; calls PUT `system/auxiliary/assess/switch-capacity {capacity}` before `node/subcard/mode`. `CapacityGroups` provides the correct mode/copy/BackupPos templates (the source's simplified first-port copy code is not authoritative over actual card XML).
- Standard presets come from `deviceconfig/connector/resolutionratio.xml`, filtered by capacity and card timing limits. Frame enums use Coefficient=0.01. Preserve CEA/DMT/etc standardType and scan type. PixelFlow getTimingParams sends timingSelect=0 for standards, 3 for custom. Native POST `interface/thumbtiming-check` checks bandwidth/frame/depth/sampling dependencies.
- Capacity changes can regenerate IDs and reset screen configuration; keep them as a separate confirmed card action, refuse pending ordinary output edits, assess before writing, preserve unrelated connector routing and verify actual topology. Timing checks must finish before any name/timing/depth writes.

## What was done

- Added `lib/output-options.js`: parses the actual installed output-card CapacityGroups, working-mode copy/BackupPos templates, per-capacity width/height/step limits, interlace gates and disabled resolutions. Standard presets come from resolutionratio.xml (including 59.94 Hz and CEA/DMT/etc), with conservative CEA fallback for old firmware without that table. P20 DL actually includes UHD up to 30 Hz; UHD 50/60 Hz requires 4K. No assumption that DL only means 1080p.
- Added `lib/output-capacity.js` and guarded `/api/output-capacity`: separate confirmed P20 card-level action. It rejects ordinary settings in this request, validates advertised capacities/ports, assesses switch-capacity resources, writes only the HDMI connector templates, preserves input/optical/AUX/MVR configuration, re-resolves changed IDs and verifies capacity/copy topology. It requires confirmation even before resource assessment because normal screen configuration can reset. Modes 4 and 8 use their own XML relationships.
- Output timing changes validate the entire requested batch, advertised standard presets and dimensions/scan limits, then run native bandwidth/frame assessment with the requested/current actual depth and sampling before any name/timing/depth writes. Screen/genlock timing changes require a separate explicit confirmation. Standard mode sends timingSelect=0; custom sends 3. Verification includes the timing mode, not only dimensions. Copy timing readouts follow their primary while copied ports remain protected.
- `public/outputs-ui.js`: compact card-capacity selector with independent-port preview and reset confirmation, separate Apply to avoid stale IDs or mixed pending edits; per-output standard resolution selector, XML limits on custom fields, fractional Hz preserved, bulk standards and unsupported-selection feedback. Changing custom numbers switches the selector to Custom. Corrected a browser-caught staging bug: an unchanged standard mode must still be included when changing the selected preset dimensions/frame, otherwise the legacy API default would select Custom.
- Added a sanitized/minimized fixture from the captured P20 card/resolution XML and an output mock, ten behavior tests in the curated runner, README and parity inventory updates. Manual copy/split/backup and detailed blanking controls remain tracked separately.
